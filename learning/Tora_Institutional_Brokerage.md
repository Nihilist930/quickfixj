## 一、奇点系统服务机构交易与零售交易有什么不同？

### 问题

奇点系统在服务机构交易和服务普通零售客户时有什么不同？

### 回答

相比服务普通零售客户，机构交易在流程、合规、风控、技术对接和运维管理方面更加复杂，主要体现在以下几个方面：

1. **交易系统评估与软件审核**

   机构客户，尤其是程序化交易客户，需要完成仿真测试，并通过 N 视界网站提交《交易信息系统合规性自检表》和《软件功能承诺函》进行软件审核。

   在《软件说明书》中，还需要单独展示暂停、快速撤销和切断开关等功能的界面截图。

2. **程序化交易报备与合规管理**

   对于可转债等品种的程序化交易，机构需要在 N 视界网站进行在线报备，并确保程序中的 `UserProductInfo` 与报备标识保持一致。

   以下情况发生变化时，通常需要重新报备：

   - 更换软件；
   - 更换程序化交易标识；
   - 调整报单速率。

   新软件还需要事先登记基本信息。

3. **异常交易行为监控**

   系统会重点监控机构投资者的程序化交易行为，包括：

   - 频繁拉抬或打压；
   - 短时间大额成交；
   - 其他可能影响交易系统安全或正常交易秩序的异常行为。

   机构投资者以产品维度进行程序化交易时，不得通过拆分产品的方式规避异常交易行为监管。

4. **风控合规模块内嵌**

   机构交易需要通过系统内嵌的合规风控模块，严格进行验资和验仓，确保交易符合监管要求。

   同时，机构还需要制定专门的业务管理和合规风控制度，健全程序化交易指令审核和监控系统。

5. **突发性事件处置**

   当不可抗力、意外事件或重大技术故障等突发事件可能影响证券交易正常进行时，机构投资者需要立即采取以下措施：

   - 暂停交易；
   - 撤销委托；
   - 及时向会员或交易所报告。

6. **多节点资金与持仓管理**

   机构客户可能涉及多个交易节点，需要进行节点之间的资金和持仓调拨，操作流程比零售交易更加复杂。

   相关操作需要参考专门的《华鑫星途 APP 多节点交易操作指引》。

7. **权限同步与业务类型更复杂**

   机构交易通常涉及更多业务类型，例如：

   - 两融；
   - 期权；
   - DMA；
   - 风险警示股票；
   - 港股通；
   - ETF 申赎。

   部分交易权限需要由运营人员手工同步到奇点系统，流程相对更加繁琐。

8. **技术对接与专属服务**

   机构客户通常需要专属技术对接团队，通过企业微信技术对接群获取接口包和详细开发文档，并完成仿真环境调试。

   相比零售客户使用标准化服务，机构客户的技术接入流程更加复杂。

## 二、奇点系统在机构交易中如何处理风控合规问题？

### 问题

奇点系统在服务机构交易时，如何处理风控和合规问题？

### 回答

奇点系统通过内嵌合规风控模块、程序化交易报备、异常行为监控和软件审核等机制，确保机构交易符合监管要求。

1. **系统内嵌风控模块**

   奇点系统内置合规风控模块，在交易过程中实时进行验资和验仓，确保交易行为符合监管要求。

2. **异常交易行为监控**

   系统会重点监控程序化交易行为，包括但不限于：

   - 频繁拉抬或打压；
   - 短时间大额成交；
   - 其他可能影响交易系统安全或正常交易秩序的异常行为。

   机构投资者以产品维度进行程序化交易时，不得通过拆分产品的方式规避异常交易行为监管。

3. **程序化交易报备与合规管理**

   对于可转债等品种的程序化交易，需要在 N 视界网站进行在线报备，并确保程序中的 `UserProductInfo` 与报备标识保持一致。

   更换软件、标识或报单速率时，需要重新报备。

   会员、公募基金管理人、私募基金管理人、合格境外投资者等机构，应当制定专门的程序化交易业务管理和合规风控制度，健全程序化交易指令审核和监控系统。

4. **交易系统评估与软件审核**

   完成仿真测试后，需要通过 N 视界的“奇点系统 → 量化交易 → 交易系统评估”入口申请软件审核。

   提交材料包括：

   - 《交易信息系统合规性自检表》；
   - 《软件功能承诺函》；
   - 按要求填写、盖章并上传的扫描件。

   按监管要求，还需要在《软件说明书》中将以下三个功能的界面截图放在单独章节中：

   - 暂停；
   - 快速撤销；
   - 切断开关。

5. **与合作机构的风控协同**

   会员接受客户程序化交易委托时，应通过委托协议等方式明确双方的权利和义务。

   当客户出现以下情况时，会员有权采取拒绝委托、撤销申报等措施：

   - 技术系统故障；
   - 可能影响交易系统安全；
   - 其他可能影响正常交易秩序的异常行为。

   会员还应有效管理客户的程序化交易行为，将其纳入异常交易监控，及时识别、管理和报告客户涉嫌异常交易的行为。

6. **突发性事件处置**

   因不可抗力、意外事件或重大技术故障等突发事件可能影响证券交易正常进行时，投资者需要：

   - 立即暂停交易；
   - 撤销相关委托；
   - 及时向会员或交易所报告。

## 三、奇点系统如何处理乱序和幽灵订单问题？

### 问题

奇点系统如何处理报单回报乱序和幽灵订单问题？

### 回答

奇点系统主要通过状态机、幂等处理、回报补充和最终状态校验等机制，处理乱序回报并避免幽灵订单。

### 1. 乱序订单处理

1. **基于订单状态和累计数据更新**

   系统基于报单回报中的以下字段更新订单最终状态，而不是简单依赖回报到达的先后顺序：

   - `OrderStatus`；
   - `VolumeTraded`（累计成交数量）；
   - `VolumeCanceled`（撤单数量）。

   例如，可能先收到撤单回报：

   ```text
   OrderStatus=PartTradeCanceled
   VolumeTraded=0
   VolumeCanceled=100
   ```

   随后收到成交回报：

   ```text
   VolumeTraded=100
   VolumeCanceled=100
   ```

   系统能够合并这些信息，最终确认订单为“部成部撤”状态。

2. **幂等性设计**

   系统需要确保同一订单的多次状态更新不会重复产生业务副作用，避免重复计算。

   同时记录所有回报的到达时间和处理顺序，便于故障排查和问题追溯。

3. **上交所部成部撤场景的特殊处理**

   针对上交所部成部撤场景，系统支持以下两种回报顺序：

   - 先收到成交回报，再收到撤单回报；
   - 先收到撤单回报，再收到成交回报。

   无论哪种顺序，系统都需要根据累计成交和撤单数据计算最终状态。

### 2. 幽灵订单处理

1. **最终状态确认**

   系统以最后一次报单回报中的 `VolumeTraded` 和 `VolumeCanceled` 为依据，确定订单最终状态，例如 `PartTradeCanceled`，避免因中间状态残留产生幽灵订单。

2. **报单回报补充机制**

   每笔成交回报后通常会跟随一笔报单回报（`OnRtnOrder`）。该回报包含报单当前状态、累计成交数量和累计成交金额，确保订单状态完整且可追溯。

3. **错误码拦截**

   对于已经处于最终状态的订单，例如：

   - 全成；
   - 部成部撤；
   - 全撤；
   - 废单。

   系统会返回 `ErrorCode=308`（VIP：报单状态异常），拒绝重复操作，防止幽灵订单产生。

### 3. 测试与验证

建议在测试环境中模拟多种回报顺序，例如：

- 先撤单、后成交；
- 先成交、后撤单；
- 重复收到同一回报；
- 收到最终状态后再次发起操作。

通过这些场景验证订单状态处理的正确性，确保生产环境稳定运行。

## 四、奇点柜台在机构交易方面有哪些核心优势？

### 问题

奇点柜台在机构交易方面有哪些核心优势？

### 回答

奇点柜台在行情速度、吞吐能力、业务覆盖、合规风控、技术接入和多节点部署等方面具有以下优势：

1. **极速行情交易速度**

   主行情采用 FPGA 硬件解码，备行情采用软件解码，并支持多路优选，能够提供微秒级时延。

2. **高稳定性和高吞吐量**

   系统吞吐量可达 60,000 笔/秒，单节点订单峰值达 800 万笔，可以满足机构客户大额、高频的交易需求。

3. **业务种类完善，支持跨市场交易**

   覆盖股票、期货、期权等多个市场，支持跨市场联动交易。

4. **符合监管要求**

   系统内嵌合规风控模块，严格进行验资和验仓，确保交易行为符合监管要求。

5. **高效技术支持**

   依托自主研发团队，为机构客户提供及时的技术支持和问题响应。

6. **极速 API 对接**

   提供标准化 API 接口，支持以下主流编程语言：

   - C++；
   - C#；
   - Python；
   - Java。

   机构客户可以据此快速完成接口接入和策略开发。

7. **双中心多节点架构**

   上海、深圳两地均部署极速节点，支持盘中资金自助划拨，初始上场资金配比可以灵活选择。

8. **两融、期权、DMA 低延时**

   - 两融业务速度与普通交易相当；
   - DMA 柜台仅增加百微秒时延；
   - 相关业务整体处于业内较低延时水平。

9. **网络优化技术**

   对低延时网卡和网络设备参数进行深度优化，API 支持 `EF_VI`，使客户能够使用相关网络优化能力。

10. **融资融券解决方案**

    奇点柜台还提供面向策略型私募的融资融券解决方案，支持：

    - 微秒级交易速度；
    - 动态保证金计算；
    - 集中度控制；
    - 两融特色技术支持；
    - 底仓 T+0 融资免息等策略优化能力。

## 五、奇点柜台支持哪些算法类型？

### 问题

奇点柜台支持哪些常见的算法交易类型？

### 回答

主要算法类型及其驱动方式如下：

| 算法类型 | 驱动方式 | 说明 |
|---|---|---|
| **TWAP**（时间加权平均价格算法） | 时间驱动（被动） | 将交易时间均匀分割，在每个分割节点提交均匀拆分的订单，适用于流动性较好的市场和订单规模较小的交易。 |
| **VWAP**（成交量加权平均价格算法） | 时间驱动（被动） | 使用过去 M 个交易日分段成交量的加权平均值预测成交量，使订单拆分更贴近市场实际成交量，是对 TWAP 的改进。 |
| **POV**（比例成交算法） | 行情驱动（被动） | 获取行情盘口数据并计算下单数量，尽量降低对价格的影响，能够较好地隐藏交易意图，适合大规模减持。 |
| **TWAP+**（改进型时间加权平均价格算法） | 时间驱动（主动） | 需要指定数量区间，并根据行情动态调整下单数量。交易成本低时多交易，成本高时少交易，通常具有较好的交易成本优势。 |
| **ICEBERG**（冰山算法） | 时间 + 行情驱动（被动） | 每次提交一定数量的委托，成交后再提交剩余数量，直到全部成交。适用于交易对盘口冲击明显、但对交易成本敏感度相对较低的场景。 |
